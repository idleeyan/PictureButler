# 图片库「人像识别 / 图片识别」功能恢复计划

版本：原生版「二」规划
日期：2026-09-12

## 一、现状摸底（已核实，非推测）

imgtag 库（E:\imgtag\db.sqlite）里**识别数据真实存在**，由 imgtag 工具生成，PictureButler 只读该库：

| 数据 | 数量 | 说明 |
|---|---|---|
| images | 4,009 | 图片主表，含 description（描述）、tags（标签）、faces_scanned（人脸扫描状态） |
| persons | 560 | 人像聚类（name / avatar_face_id / ignored） |
| image_faces | 1,724 | 人脸框（image_id / person_id / bbox / embedding / score） |
| tags + image_tags | 4,378 / 20,724 | 标签体系与图片-标签关联 |
| images_fts | 4,009 | 全文索引（描述/文件名可搜索） |

**关键结论**：
1. 「人像识别」= imgtag 已做人脸聚类（560 个人像、1724 个脸框），但旧版 PictureButler 只显示了「人物 560」这个数字，**没有人像视图**——这是可恢复的核心。
2. 「图片识别」= 描述（description）与标签（tags）已存在，可检索；**识别生成**（对未识别图片调用模型打标）旧版从未做过，需要新能力或外部工具配合。

## 二、目标功能（分两批）

### 第一批：呈现已有识别数据（工作量小，纯读库）
1. **人物视图**：图片库新增「人物」页签
   - 人物卡片网格：头像（avatar_face_id 对应的人脸缩略图）+ 姓名 + 照片数
   - 点击人物 → 该人物的全部照片（image_faces.person_id 反查 images）
   - 图片详情里显示人脸框（bbox）标注
2. **标签筛选**：图片库按标签点选筛选（tags 数据已有）
3. **识别状态**：图片详情显示「已扫描/未扫描」（faces_scanned），未扫描的可标记为待处理

### 第二批：识别生成（需要外部模型/工具，先定方案）
4. **批量打标**：对未扫描/无描述图片，调用本地模型生成描述+标签
   - 候选通道：ComfyUI WD14/Tagger 工作流（用户本地已有 ComfyUI）
   - 或 imgtag 自身如果带 CLI/批处理能力，直接调它
5. **人脸重聚类**：新图片入库后自动接入 imgtag 的人脸流程（依赖 imgtag 是否提供命令）

## 三、实现方案（原生版）

```
ImgtagService 扩展：
  Persons()            → 人物列表（id/name/avatar/photoCount/ignored）
  PersonPhotos(id)     → 该人物全部图片（分页）
  FacesByImage(id)     → 图片的人脸框列表（bbox 用于标注）
  Tags()               → 标签列表（按使用次数降序）

UI（图片库视图增加页签：全部 / 人物 / 标签）：
  人物页签 → 人物卡片网格（复用图片卡片样式）→ 点击进人物相册
  标签页签 → 标签云/列表 → 点标签筛图
  图片详情 → 人脸框标注（Canvas 叠在图片上）
```

## 四、需要你确认的决策点

1. **「图片识别」的期望深度**：
   - A：只恢复「呈现与检索」（人物视图 + 标签筛选 + 人脸框标注）——数据已有，本周内可完成
   - B：A + 对未识别图片调用模型打标（需要选模型通道：ComfyUI WD14 工作流 / imgtag CLI / 其他）
2. **人物视图入口**：图片库内页签，还是独立左侧导航项？
3. **人脸框标注**：图片详情大图里画框（黄色框+名字），是否要？

## 五、工作量预估

- 第一批（A）：服务层 4 个查询 + 人物视图 + 标签筛选 + 人脸标注 ≈ 原生版「二」或「三」一个版本内
- 第二批（B）：模型通道打通 + 批处理队列 + 进度 UI ≈ 独立一个版本

## 六、风险

- 人脸框 bbox 是 imgtag 的坐标系（相对原图比例），需确认单位（0-1 或像素）再叠加
- embedding 字段大（1724 条），列表查询不要拖出 embedding，只按 person_id 聚合
- persons.ignored 标记的人像应默认过滤（imgtag 的「忽略」语义）
