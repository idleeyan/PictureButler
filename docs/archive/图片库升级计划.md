# 图片库升级计划

版本：v2（按代码与数据库实测修订）
日期：2026-09-12
适用：WPF 原生版（`src-native`，当前发布主线）
基线：0.19.0「十九」——已含「换封面修复」与「0 张人物显示过滤」

> v2 相对 v1 的变化：①修正与现状不符的前提（0 张人物、imgtag 读写边界、各项数量）；
> ②把「虚拟化」从可选提为必做（直击"拖动窗口都卡"）；③把「人脸/AI 打标闭环」前移（用户高频点名）；
> ④防抖改用一套 CancellationTokenSource，不再自造 DispatcherTimer；⑤缩略图复用 imgtag 的
> `.faces/.thumbs`，不另起缓存；⑥补齐空人物的存量清理与防复发、ComfyUI 新增提醒、内存验收。

### 1.3 明确缺陷（按用户痛点排序）

#### A. 卡顿 / 内存（用户骂得最多：移动窗口都卡、内存巨大）

| 位置 | 问题 |
|------|------|
| 列表容器 | `ItemsControl + WrapPanel` **无 UI 虚拟化**，一次性把全部人物卡（355）/整页图卡建进可视化树，是"拖动卡"的主因——查询再快也救不了渲染线程 |
| 缩略图 | 每次进页在 `Task.Run` 同步 `DecodePixelWidth` 解码整页；**无磁盘缓存**，翻回重复解码；离屏图不释放，长时间刷内存线性涨 |
| 人物列表 | 一次查询全部人物并解码全部封面，无分页 |
| 标签列表 | 一次塞入 4459 个芯片，WrapPanel 无虚拟化 |
| `CurrentPerson()` | 为取一个人物整表 `Persons()` 再 FirstOrDefault |

#### B. 防抖 / 竞态

| 位置 | 问题 |
|------|------|
| `ImgSearchBox.TextChanged` | 每次按键立刻 `_imgPage=0; LoadImgPageAsync()`，无防抖无取消；连打 10 字 = 10 次查询 + 10 次解码，且后发先至覆盖结果 |
| `SearchBox`（提示词） | 同样无防抖，同步 `ApplyFilter()` |
| `LoadImgPageAsync` | 无 CancellationToken；快速翻页/切页签/点人物时并发互相覆盖 `ItemsSource`（注意：token 只能丢弃过期结果，**不能中断正在跑的 SQLite 查询**） |
| 翻页 / 页签切换 | 连点并发、fire-and-forget，无取消上一次 |

#### C. 功能闭环缺口（用户多次点名）

| 缺口 | 现状数据 |
|------|------|
| 人脸识别未全量完成 | faces_scanned=0 共 **236 张**；缺"多选 → 排队识别 + 进度" |
| AI 打标队列 | 覆盖率虽高，但同样缺批量队列与失败重试 |
| ComfyUI 新增入库 | 监听入库正常，但**无视觉提醒**，用户感知弱 |
| 查看器无前后切换 | 看图必须关窗再点下一张 |

#### D. 筛选 / 搜索质量

| 问题 | 说明 |
|------|------|
| 无排序 | 固定入库倒序，不能按文件名/尺寸/大小；且双库时间基准不一，混排会跳 |
| 无状态筛选 | 不能筛「未识别人脸 / 已打标 / 有关联词」 |
| 无文件夹筛选 | 来源夹只能在设置管理，列表内不能按夹过滤 |
| 搜索用 LIKE | imgtag **已有 `images_fts`（实测存在）**，WPF 侧未用，大库慢且无相关度 |
| 标签不可组合 | 进一个标签相册后不能叠加第二标签 |
| HasPrompt 内存滤 | 若在 SQL 分页之后再内存过滤，会导致每页数量不齐、总数对不上 |

#### E. 交互 / 可观测

无加载态、搜索无高亮、全选仅当前页、网格无方向键/Enter、无查询耗时与缓存命中日志（"还卡不卡"无法回归）。

### 1.4 数据写入边界（重要，避免后续误判）

当前是**混合写库**，不是"imgtag 只读"：

- **人物元数据（重命名/换封面/合并/删除）**：C# 经 ATTACH **直连写** `it.persons / it.image_faces`（短事务）。
- **识别结果（人脸扫描、聚类、AI 打标）**：走 imgtag 的 HTTP API（127.0.0.1:8520）。
- 同一个 `db.sqlite` 被 Rust 服务与 C# 同时打开：必须确认 **WAL 模式 + busy_timeout**，写事务尽量短，禁止在事务里夹带图片解码/网络等待。

## 二、升级目标

1. **不卡**：列表虚拟化/分页 + 缩略图磁盘缓存复用 + 离屏释放，拖动窗口流畅，长刷内存不线性涨。
2. **跟手**：搜索/筛选/翻页/切页签一套 CTS 防抖 + 过期结果丢弃，杜绝乱跳错页。
3. **干净**：空人物存量一次清掉、写操作后自动 prune，列表永不再出现 0 张。
4. **闭环**：236 张未识别可批量跑完；ComfyUI 入库有明确视觉提醒。
5. **好用**：排序、状态/文件夹筛选、FTS、标签组合、查看器前后切换、键盘导航。
6. **不破坏**：提示词 / ComfyUI / 浏览器扩展链路不动；识别写库仍走 HTTP。

## 三、架构原则

```
UI 事件 ──► 同一把 CancellationTokenSource（防抖=延迟触发，加载=取消旧请求）
                    │
                    ▼
             Query（SQL 集中在 ImageLibraryService，UI 不写 SQL）
                    │  token 已取消 → 结果丢弃，不碰 ItemsSource
                    ▼
        先绑卡片壳（文件名+占位）──► ThumbProvider（.faces/.thumbs/自建缓存）异步按可见优先填充
```

- **一套 token 同时管防抖与取消**：不再引入 DispatcherTimer 自造类。
- **单一飞行结果**：只允许"最新一次加载"写 `ItemsSource / 计数 / 页码`。
- **缩略图与列表解耦**：元数据先出、图片后补；`PersonItem` 已实现 INPC，`ImgItem` 需补上。
- **缩略图三级来源**：imgtag `.faces`（人脸封面）→ imgtag `.thumbs`（整图）→ 程序自有缓存（仅自建索引独有图）。
- **查询层可测**：排序/筛选/邻接全部下沉到 `ImageLibraryService`。

## 四、分阶段实施

### 阶段 0（0.20.0「二十」）：空人物清理 + 防抖取消 + 入库提醒 —— 约 1 天

#### 0.1 空人物存量清理与防复发（显示层已完成，本步补数据层）

- `ImageLibraryService` 新增 `PruneEmptyPersons()`：
  - 删除 `ignored=0` 且**不存在任何"仍指向有效图片的人脸"**的 person（与显示层同一套双层 EXISTS 判定，保证"看不见的=会被清的"口径一致）；
  - **保留 `ignored=1`**（用户主动忽略）；
  - 返回清理条数。
- 触发时机：①设置页加「清理空人物」按钮（显示将删条数，二次确认）；②程序启动、识别库连接成功后**最多自动执行一次**（静默，写日志）。
- 防复发：在 `MergePersons / DeletePerson` 及人脸清理事务**末尾**，对受影响目标统一 prune 一次（迁移/删脸后变空的源人物即时删除）。
- 验收：执行后 `ignored=0` 记录数 = 界面可见数 = 355；`ignored=1` 109 条不变；再做一次"删除人物（连脸）"不产生新空壳。

#### 0.2 一套 CTS 的防抖 + 取消（替代 v1 的 DebounceDispatcher）

```csharp
private CancellationTokenSource? _imgListCts;

// 输入：取消上一次 → 延迟 300ms → 触发；Enter 立即触发
private void ImgSearch_OnTextChanged()
{
    _imgListCts?.Cancel();
    var cts = _imgListCts = new CancellationTokenSource();
    var token = cts.Token;
    _ = Task.Run(async () =>
    {
        try { await Task.Delay(300, token); } catch (OperationCanceledException) { return; }
        if (token.IsCancellationRequested) return;
        _imgPage = 0;
        await LoadImgPageAsync(token);
    });
}
```

- `LoadImgPageAsync(CancellationToken token)`：进入先取消旧 CTS、挂新 token；**每个查询前后** `token.ThrowIfCancellationRequested()`；`Dispatcher.InvokeAsync` 绑定前再判 `IsCancellationRequested`，过期直接丢弃。
- 明确边界：**同步 SQLite 查询本身不可中断**，期间占用线程属正常，取消只保证"过期结果不上屏、不重复解码缩略图"。
- 覆盖调用点：搜索、Enter、翻页、页签切换、人物/标签点击、返回、识别完成刷新、删除后刷新。
- 提示词 `SearchBox` 同模式（250ms）。

#### 0.3 ComfyUI 新增入库视觉提醒

- 监听到新增图片入库时：主窗口右下角弹轻量 Toast（"新增 N 张 · 点击查看"），并在"图片库"侧栏项加小圆点计数，点击后清除；不抢焦点、不打断当前操作。

#### 0.4 幽灵清理互斥

- 3 秒清理 timer 仅在网格可见时跑；与加载用同一 `_imgLoading` 旗标互斥，避免边加载边删导致闪烁。

#### 0.5 阶段验收

- 快打 15 字：**最终仅 1 次查询、且缩略图仅解码 1 批**（加临时计数日志佐证）。
- 连点"下一页"5 次：停在正确页、无回跳；输入到一半切"人物"再切回，无人物数据残留在网格。
- 空人物清理后，库记录数与界面数一致，ignored 人物不受影响。

#### 1.1 列表虚拟化 / 分页（先解决"拖动卡"）

- 网格：`ItemsControl+WrapPanel` 换支持虚拟化的容器（自绘 `VirtualizingWrapPanel`；`ScrollViewer` 开 `IsVirtualizing=True / VirtualizationMode=Recycling`）。
- 人物：超过 120 人启用分页或"加载更多"；标签默认 Top 200（按次数）+ 标签搜索框（防抖 200ms），可展开全部。
- 过渡兜底（若自绘面板耗时）：先把网格页大小降到 40、人物/标签分页，当天即可减负，虚拟化随后替换。
- `CurrentPerson(id)` 改单条 `WHERE id=?`，禁止整表。

#### 1.2 缩略图：复用 imgtag 缓存，不另起炉灶

- 人脸封面：直接用 `imgtag/.faces/{faceId}.jpg`（换封面链路已用），缺失时向 8520 请求回写。
- 整图缩略图：优先 `imgtag/.thumbs/{约定名}`；自建索引独有、imgtag 没有的图，才落 `%LOCALAPPDATA%\com.picturebutler.app\thumbs\`。
- 缓存 key = `SHA1(path+mtime+size+decodeWidth)`，文件改动自动失效；网格宽 320、人物封面 160；单张约 50KB JPEG，设置页可一键清空。
- 好处：与 imgtag 网页端共用一份缩略图，不重复占盘、不重复解码。

#### 1.3 先壳后图 + 内存治理

- `LoadImgPageAsync` 只查元数据立即绑定；`SemaphoreSlim(4)` 按可见优先补 `Thumb`，翻页/取消时停掉未完成填充。
- `ImgItem` 补 `INotifyPropertyChanged`（与 `PersonItem` 一致）；填图回 Dispatcher 前校验 token。
- 虚拟化回收容器时释放对应缩略图引用；`DecodePixelWidth` 严格按显示尺寸，禁止整图解码。

#### 1.4 验收

- 二次进同一页：缩略图近瞬出（日志 HIT）；人物 355 人占位 <200ms 出现、封面渐进填充无白屏。
- **连续滚动 5 分钟，进程内存不线性增长**（任务管理器取样，趋于平稳）。
- 拖动窗口、快速滚动全程不掉帧；标签不再一次塞 4459 个芯片。

### 阶段 3（0.23.0「二十三」）：排序 / 筛选 / FTS / 标签组合 —— ✅ 已完成并发布（2026-09-12 深夜）

> - **FTS**：it 侧 `images_fts MATCH`（ATTACH 跨库必须用裸表名 `images_fts`，带 `it.` 前缀会报错），启动探测、异常/特殊字符静默回退 LIKE；MATCH 串拆词加双引号 phrase。
> - **来源**：自建 folder ∪ it 路径目录（`substr(path,1,length(path)-length(filename)-1)`）合并去重，下拉选择。
> - **标签 AND 组合**：`HAVING 关联标签数 = n`；标签相册新增"＋加入筛选(且)"，回全部页以可移除芯片（#标签 ×）展示交集。
> - UI：搜索行右侧新增排序/状态/来源三个深色紧凑下拉（App.xaml FilterCombo 样式）；空结果显示居中提示。
>
> **验收实测**：Python 独立复算 + 真机双验证——总数 4228、未人脸/已人脸互补且和=总数；已打标 4043；FTS 与 LIKE 搜 "woman" 均=5；
> 来源选 ComfyUI output=837（与库内完全一致）、来源共 60 项；4 种排序首项正确（文件名从 00.png 起、大小/像素大图优先）；
> 标签 1∩39 交集=166 且 ≤ 任一单标签、与共现数完全一致；真机走"女性标签→加入筛选→878 张→点 × 移除→恢复全部"闭环；

#### 3.1 工具栏

```
[全部][人物][标签] | 排序[入库↓|入库↑|文件名|大小|像素] | 来源[全部|各来源夹…]
                  | 状态[全部|未识别人脸|已识别人脸|已打标|有关联词]
```

#### 3.2 排序（统一时间口径）

- 自建库 `added_at` 与 imgtag `created_at` 先归一到同一 unix 秒（`COALESCE`），再排序，避免混排乱跳。

| sort | ORDER BY（归一后） |
|------|----------|
| date_desc（默认） | 时间 DESC |
| date_asc | 时间 ASC |
| name | `filename COLLATE NOCASE` |
| size | `file_size DESC` |
| pixels | `width*height DESC` |

#### 3.3 状态筛选（必须下推 SQL，不能分页后内存滤）

- `faces_scanned`、`description<>''` 直接进 WHERE 与 Count，保证每页满页、总数一致。
- "有关联词"跨 prompts 库：先取匹配文件名/路径集合再 `IN` 下推，不在分页结果上后滤。

#### 3.4 FTS 搜索

- imgtag 侧 `images_fts MATCH ?`（表已确认存在），启动探测 `sqlite_master`，任何异常静默回退 LIKE；查询串去首尾/全角空格，空串走全量。命中高亮列 P2。

#### 3.5 标签组合

- `SearchByTagIds(ids)`：`GROUP BY image_id HAVING COUNT(DISTINCT tag_id)=n`；顶部以可移除芯片展示已选标签。

#### 3.6 验收

切换排序即时且无并发错乱；"未识别人脸"数 = 库内 236（随阶段2递减）；标签 A+B 结果 ⊆ A；各状态筛选每页满页、总数一致。

### 6.2 关键 SQL

```sql
-- 空人物判定/清理（与显示层同口径；ignored=1 保留）
DELETE FROM persons WHERE ignored=0 AND NOT EXISTS (
  SELECT 1 FROM image_faces f JOIN images i ON i.id=f.image_id
  WHERE f.person_id=persons.id);

-- 状态：未识别人脸（下推 WHERE/Count）
SELECT ... FROM it.images WHERE faces_scanned=0

-- 标签组合
SELECT image_id FROM it.image_tags WHERE tag_id IN (?,?,?)
GROUP BY image_id HAVING COUNT(DISTINCT tag_id)=3

-- FTS（已确认存在，失败回退 LIKE）
SELECT rowid FROM images_fts WHERE images_fts MATCH ?
```

### 6.3 混合写库纪律

- 确认 imgtag `db.sqlite` 为 WAL；C# 连接串设 `Busy Timeout`（建议 5000ms）。
- 直写 `it.*` 的事务保持极短：只做 UPDATE/DELETE，不在事务内解码图片或 await 网络。
- 识别类写入始终走 HTTP，避免与 Rust 侧聚类事务竞争。

### 6.4 回归清单

### 6.5 风险与缓解

| 风险 | 缓解 |
|------|------|
| Rust 与 C# 同写 db.sqlite | WAL + busy_timeout + 短事务；识别写走 HTTP |
| 虚拟化自绘面板工作量 | 先"降页大小+分页"当天兜底，面板随后替换 |
| 缓存目录膨胀 | LRU/一键清理；单张约 50KB；优先复用 imgtag 缓存 |
| FTS 与 imgtag 版本差异 | 探测 sqlite_master，失败回退 LIKE |
| CTS 误取消正在看的结果 | 只丢弃"非最新一次"，最新 token 不受影响；查询不可中断属预期 |
| 查看器跨页序列断裂 | 用过滤结果集邻接 id，而非当前页数组 |
