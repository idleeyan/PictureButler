# PictureButler UI 视觉升级计划

> **文档标识**：本计划由 TraeDesign 生成于 2026-09-13，为 PictureButler 项目的 UI 视觉升级方案。请勿与其他智能体生成的同名文档混淆。

版本：v1.0  
日期：2026-09-13  
适用：PictureButler Windows 原生版 + imgtag Web 前端 + 浏览器扩展

---

## 一、项目理解

PictureButler 是一款 Windows 11 本地桌面程序，核心定位是**二合一生产力工具**：

1. **AI 提示词管理**：管理 prompts.db，通过浏览器扩展把星标提示词一键写入网页输入框。
2. **本地 AI 图片相册**：基于 imgtag（Rust cdylib）对本地图片做人脸识别、AI 打标、标签检索、人物聚类。

当前 UI 分为三条线：

| 产品线 | 技术栈 | 主要入口 | 当前状态 |
|---|---|---|---|
| 桌面主程序 | WPF / .NET 10 | MainWindow、ImgViewerWindow、设置页 | 功能已较完整（0.24.0），视觉偏原生默认风格 |
| imgtag Web 前端 | Vue 3 + Tailwind CSS + 内联 CSS | `index.html`（由本地 HTTP 服务提供） | 暗色主题已成型，但色彩/组件较零散 |
| 浏览器扩展 | Manifest V3 + 原生 DOM | `popup.html` | 340px 小弹窗，视觉简陋 |

本计划不改动架构与核心技术栈，只在现有实现基础上做**系统性的视觉与体验升级**。

## 二、现状诊断

### 2.1 视觉层面

1. **色彩系统不统一**
   - Web 端同时存在 Tailwind 默认色板（`bg-gray-900`、`border-gray-800`）与自定义 `:root` 变量（`--bg: #0b1120`），两套蓝色也不一致（Tailwind `blue-500 #3b82f6` 与自定义 `--accent: #3b82f6` 刚好相同，但使用方式混乱）。
   - 状态色直接使用红/绿/黄/紫，未做语义化命名，扩展改色困难。
   - 扩展弹窗 `#1B1E28` 与 Web 端 `#0b1120` 背景色不统一，品牌感割裂。

2. **字体与排版缺乏层级**
   - Web 端字号跨度大（10px ~ 18px），大量地方混用 `text-xs`、`text-sm` 与硬编码 `font-size`。
   - 行高、字重未规范，标签/人物/状态数字的对比度不足。
   - 中文环境使用系统默认字体，未指定回退栈与字重策略。

3. **圆角、阴影、边框不规范**
   - 卡片圆角 8px、10px、14px 并存；按钮圆角 6px、8px、10px 并存。
   - 阴影只在 `image-card:hover` 出现，其他浮层、模态框、Toast 未统一。
   - 分割线使用 1px `border-gray-800`，层级感弱，侧栏边界不清晰。

4. **图标系统缺失**
   - 使用大量 Emoji（📁、🏷、👤、✨ 等）作为图标，不同系统显示效果不一致，且无法随主题变色。
   - 缺少统一图标库；设置按钮直接用 `⚙` 字符，尺寸夸张（52px × 52px，font-size 28px）。
   - 扩展图标为静态 PNG，未提供反白/高分辨率变体。

5. **图片与缩略图呈现粗糙**
   - 卡片图片固定 200px 高度，未适配不同比例照片，竖图被过度裁剪。
   - 人物头像为方形，没有人脸居中、圆角头像或占位图策略。
   - 空状态使用大 Emoji，缺少插画或品牌化空状态。

### 2.2 交互层面

1. **信息密度过高**
   - 顶部状态栏塞入 7 组统计数字 + 2 个下拉框 + 3 个按钮，换行后显得杂乱。
   - 人物面板一次展示扫描/重扫/归类/批量/忽略等多组按钮，认知负担重。

2. **反馈不够细腻**
   - Toast 为简单色块，没有图标前缀动画。
   - 进度条位于右下角，颜色与全局进度语言不统一。
   - 模态框打开/关闭无过渡，十多个弹窗风格各异。

3. **键盘与可访问性弱**
   - 大量按钮为纯图标或 Emoji，缺少 `aria-label`。
   - 焦点态未设计，Tab 导航不可见。
   - 暗色主题对比度部分区域偏低（`text-gray-600` 在 `bg-gray-900` 上）。

4. **扩展体验简陋**
   - 弹窗宽度固定 340px，长标题/内容截断不优雅。
   - 未连接状态只是红色文字，缺少重试引导。
   - 星标列表与搜索框视觉层级不明显。

---

## 三、升级目标

1. **建立一套统一的设计系统**：让 WPF、Web、扩展三条线在色彩、字体、组件、图标、动效上保持一致。
2. **提升专业感与品牌感**：用品牌蓝为主轴，辅以功能色，替代零散 Emoji，打造「本地 AI 工具」应有的精致度。
3. **降低认知负荷**：重组信息层级，减少单次入眼元素，重要操作突出，次要操作收敛。
4. **强化图片浏览体验**：优化卡片比例、缩略图占位、人物头像、查看器视觉。
5. **补齐动效与反馈**：统一的 Toast、模态、加载、进度、空状态、悬停/点击反馈。
6. **改善可访问性**：提高对比度、统一焦点环、补充语义标签。

## 四、设计系统升级

### 4.1 色彩系统

采用单一语义化色彩变量表，三条线共用同一套色值。

```css
:root {
  /* 背景 */
  --bg-base: #080c14;        /* 最底层背景 */
  --bg-surface: #0f1524;     /* 卡片/面板背景 */
  --bg-elevated: #151d2e;    /* 浮层/模态/Popover */
  --bg-overlay: rgba(0,0,0,0.72);

  /* 边框 */
  --border-subtle: rgba(148,163,184,0.08);
  --border-default: rgba(148,163,184,0.14);
  --border-strong: rgba(148,163,184,0.22);
  --border-focus: #60a5fa;

  /* 文字 */
  --text-primary: #f1f5f9;
  --text-secondary: #94a3b8;
  --text-tertiary: #64748b;
  --text-disabled: #475569;

  /* 品牌/主色 */
  --brand-400: #60a5fa;
  --brand-500: #3b82f6;
  --brand-600: #2563eb;
  --brand-soft: rgba(59,130,246,0.12);

  /* 功能色 */
  --success-400: #4ade80;
  --success-500: #22c55e;
  --success-soft: rgba(34,197,94,0.12);
  --warning-400: #fbbf24;
  --warning-500: #f59e0b;
  --warning-soft: rgba(245,158,11,0.12);
  --danger-400: #f87171;
  --danger-500: #ef4444;
  --danger-soft: rgba(239,68,68,0.12);
  --cyan-400: #22d3ee;
  --cyan-500: #06b6d4;
  --cyan-soft: rgba(6,182,212,0.12);
}
```

升级要点：
- Web 端删除内联硬编码颜色，全部改用 CSS 变量或 Tailwind 配置映射。
- WPF 端在 `App.xaml` 建立对应 `SolidColorBrush` 资源字典。
- 扩展弹窗背景统一为 `--bg-surface`，与 Web 端一致。

### 4.2 字体与排版

```css
--font-sans: "Inter", "PingFang SC", "Microsoft YaHei", "Segoe UI", system-ui, sans-serif;
--font-mono: "JetBrains Mono", "SF Mono", Consolas, monospace;
```

字号规范（桌面/Web 以 14px 为基准，扩展以 13px 为基准）：

| Token | 桌面/Web | 扩展 | 用途 |
|---|---|---|---|
| text-xs | 11px | 10.5px | 辅助说明、计数、标签 |
| text-sm | 13px | 12px | 按钮、输入框、列表正文 |
| text-base | 14px | 13px | 正文、卡片标题 |
| text-lg | 16px | 14px | 侧栏标题、模态标题 |
| text-xl | 20px | — | 大标题、空状态主文案 |
| text-2xl | 24px | — | 启动页/品牌标题 |

字重规范：
- 标题使用 600（semibold），正文 400，按钮 500，统计数字 600。
- 避免过多 700/800，减少视觉噪音。

### 4.3 间距、圆角与阴影

间距基数 4px，统一使用 4/8/12/16/20/24/32/40 八个档位。

| 元素 | 圆角 | 说明 |
|---|---|---|
| 小按钮/输入框/标签 | 8px | 高密度区域 |
| 卡片/面板/弹窗按钮 | 12px | 主要内容容器 |
| 大卡片/模态框/Toast | 16px | 浮层与独立模块 |
| 头像/圆形按钮 | 9999px | 完全圆角 |

阴影：
- 卡片悬停：`0 4px 20px rgba(0,0,0,0.35)`
- 模态框：`0 24px 60px rgba(0,0,0,0.55)`
- Toast：`0 8px 24px rgba(0,0,0,0.4)`
- 批量工具栏/进度面板：`0 -4px 24px rgba(0,0,0,0.3)`

### 4.4 图标系统

统一引入图标字体或 SVG 图标库（推荐 [Lucide](https://lucide.dev/)，MIT 协议，风格简洁）：

- 替换所有 Emoji 图标：
  - 📁 → `folder`
  - 🏷 → `tag`
  - 👤 → `user`
  - ✨ → `sparkles`
  - ⚙ → `settings`
  - ✕ → `x`
  - ✎ → `pencil`
  - ♻ → `refresh-cw`
  - 🗑 → `trash-2`
  - 🔍 → `search`
  - 💾 → `hard-drive`
  - ★/☆ → `star` / `star-off`
  - ✓ → `check`
- 图标尺寸分 16/20/24px 三档，颜色跟随文字或语义色。
- 所有图标按钮设置 `aria-label`，保证屏幕阅读器可访问。

扩展图标建议升级：
- 提供 16/32/48/128px SVG 源文件，导出时做 2px 安全边距。
- 提供浅色/深色浏览器工具栏反白版本。

### 4.5 动效与反馈

| 场景 | 动效 |
|---|---|
| 按钮悬停 | background/border 150ms ease，图标 100ms translateY(-1px) |
| 卡片悬停 | translateY(-3px) + shadow 200ms ease |
| 模态打开 | 背景 150ms fade-in，内容 200ms scale(0.96→1) + fade |
| Toast 进入 | 从底部滑入 + fade 250ms ease-out |
| 进度条 | width 过渡 300ms ease，颜色渐变 brand-500 → cyan-400 |
| 图片加载 | shimmer 骨架 → 淡入显示 200ms |
| 选中态 | ring 宽度/颜色 150ms，checkmark 缩放弹出 |

注意：WPF 端部分动效受性能约束，列表滚动区域禁用昂贵效果。

## 五、分界面升级方案

### 5.1 桌面主程序（WPF）

当前 WPF 界面以原生控件为主，视觉较素，重点做「品牌化 + 控件精致化」。

#### 5.1.1 全局

- 窗口背景改为 `#080c14`，标题栏跟随系统暗色或自定义暗色标题栏。
- 全局字体改为 Inter + PingFang SC 回退，字号按上述规范对齐。
- 在 `App.xaml` 建立统一资源字典：`PB.Brushes`、`PB.TextStyles`、`PB.ButtonStyles`、`PB.ComboBoxStyles`。
- 所有按钮、输入框、下拉框、复选框统一圆角 8px/12px。
- 统一焦点环：2px `--border-focus` 外描边，键盘导航可见。

#### 5.1.2 图片库主界面

- **顶部工具栏**：
  - 左侧放「全部 / 人物 / 标签」分段控件（Segmented Control），替代当前页签或分散按钮。
  - 右侧搜索框加宽，内部前置 `search` 图标；排序/状态/来源使用简洁图标+下拉组合，减少文字长度。
  - 统计数字精简为 4 组：总数、已完成、待处理、失败；其余信息 hover 时显示 tooltip。
  - 「全部标记」「刷新」「批量」按钮按主次分色：主操作 brand，次操作 surface。

- **图片网格**：
  - 卡片统一 12px 圆角，边框 1px `--border-default`，悬停时边框变为 `--brand-400` 并显示阴影。
  - 图片区域采用宽高比容器（建议 4:3 默认，可切换 1:1/3:2），竖图使用 `object-fit: contain` 加背景填充，避免过度裁剪。
  - 状态角标缩小并带图标：`done` 绿色 check、`pending` 黄色 spinner、`failed` 红色 x。
  - 卡片底部信息简化：保留文件名与拍摄日期，尺寸/大小 hover 显示。
  - 多选复选框使用统一 20px 自定义样式，选中态 brand 背景 + 白色 check。

- **人物卡片**：
  - 头像改为 1:1 圆形或 16px 圆角方形，采用人脸居中裁剪。
  - 姓名使用 text-base semibold，照片数使用 text-xs `--text-tertiary`。
  - 悬停显示快捷操作：重命名、换封面、合并。

- **标签云**：
  - 标签 chip 高度 28px，圆角 14px，背景 `--brand-soft`，文字 `--brand-400`。
  - 已选中态背景 brand-500，文字白色。
  - 提供「展开全部」与搜索框，默认显示 Top 200。

- **侧栏**：
  - 文件夹列表项高度 40px，hover 背景 `--bg-elevated`。
  - 当前选中项左侧加 3px brand 竖线指示，背景 `--brand-soft`。
  - 底部系统状态区使用小图标 + 一行文字，设置按钮尺寸回归 32px。

#### 5.1.3 图片查看器

- 窗口标题栏隐藏或极简，图片区域背景纯黑 `#000`。
- 左右切换按钮改为 48px 圆形半透明浮层，悬停显示。
- 顶部信息条：居中显示 `当前 / 总数`，左侧返回/关闭，右侧操作菜单（删除、打开目录、壁纸、识别）。
- 人脸框样式：2px brand 描边，带小标签显示人名，hover 高亮。
- 元数据面板改为右侧抽屉（可收起），12px 圆角，背景 `--bg-surface`。
- 加载原图时显示模糊缩略图放大占位 + 中心 spinner。

#### 5.1.4 设置页

- 分组使用卡片式面板，16px 圆角，`--bg-surface` 背景。
- 滑块替换为统一风格：track 高度 6px，thumb 20px，当前值在右侧显示数字。
- 路径输入框加文件夹选择按钮，避免用户手输。
- 危险操作（清空缓存、清理空人物）使用 danger 按钮，带二次确认。

#### 5.1.5 Toast 与进度

- Toast 统一从右下角滑入，左侧带语义图标，右侧可手动关闭。
- 进度面板使用 brand 渐变进度条，文件名 tooltip 显示完整路径，取消按钮始终可见。

### 5.2 imgtag Web 前端（Vue + Tailwind）

Web 端是本次升级的重点，因其代码可见、改动成本低、视觉问题最集中。

#### 5.2.1 整体布局

- 三栏布局保留，但调整比例：左侧文件夹栏 260px，中间标签/人物栏 260px，主区域自适应。
- 侧栏与主区域之间使用 subtle 分割线，避免深色块糊在一起。
- 顶部工具栏改为 sticky，高度 56px，背景加底部细线。

#### 5.2.2 左侧文件夹栏

- Logo 区：移除渐变方块里的字母 `I`，改用统一 SVG Logo（36px）。
- 标题使用 `text-lg font-semibold`，版本号显示在标题下方 tiny 文字。
- 添加文件夹输入框与按钮合并为单行输入框，右侧内嵌 `plus` 图标按钮，减少视觉碎片。
- 文件夹项统一 40px 高度，当前选中态左侧 3px brand 指示条。
- 操作按钮（重命名/删除）默认隐藏，hover 整行时显示 32px 图标按钮。

#### 5.2.3 中间标签/人物栏

- Tab 切换改为分段控件，当前项带下划线或背景填充。
- 搜索框统一为带图标的输入框，高度 36px。
- AND/OR 切换改为胶囊分段控件。
- 标签列表项增加 hover 背景，选中态使用 brand-soft 背景 + brand 文字。
- 人物网格使用 4 列紧凑布局，头像圆角 12px，底部渐变遮罩改为从 bottom 起的 60% 渐变。
- 人物批量操作工具栏固定在面板底部，左侧显示已选数量，右侧横向排列图标按钮。

#### 5.2.4 主内容区

- 顶部统计栏精简：
  - 当前路径/人物使用面包屑样式。
  - 统计数字合并为「N 张 · M 已标记 · K 待处理」，失败数用 danger 色单独显示。
  - 排序/状态/来源下拉框统一尺寸与样式。
- 搜索框占据主区域第二行，宽度最大 720px 居中或左对齐，placeholder 使用 `--text-tertiary`。
- 筛选条件使用 chip 行展示，每个 chip 带 `x` 可移除。
- 图片网格：
  - 默认 4 列，根据窗口宽度响应为 3/2/1 列。
  - 卡片比例默认 4:3，支持切换 1:1/16:9/原始比例。
  - 图片加载时显示 shimmer 骨架，加载完成后淡入。
  - 状态角标改为图标化小圆点 + 文字组合，避免大面积色块。
  - 卡片标签最多显示 2 个，其余 hover 显示 tooltip。
- 时间轴视图：
  - 时间标题使用 `text-sm font-semibold --text-secondary`，减少蓝色使用。
  - 时间轴点改为小圆环，选中/悬停时放大。
  - 分组之间增加 32px 间距，减少拥挤感。

#### 5.2.5 详情模态框

- 模态框最大宽度 1200px，圆角 20px，内容区无边框阴影内部隔断。
- 左侧图片区使用深色背景，图片最大化显示，操作按钮（下载、删除、壁纸）浮于图片底部。
- 右侧信息面板宽度固定 320px，分组展示：
  - 文件信息（4 项小卡片合并为 2×2 简洁网格）。
  - 描述：可点击编辑，编辑态边框高亮。
  - 标签：chip 列表，编辑态提供输入建议。
  - 人脸：头像列表，点击可跳转人物。
- 关闭按钮改为 40px 圆形图标按钮，位于右上角。

#### 5.2.6 批量与设置模态框

- 所有模态框标题统一 18px semibold，底部按钮左取消右确认。
- 批量打标签：提供输入建议下拉，常用标签快速选择。
- 批量删除：危险操作使用 danger 按钮，二次确认文案突出影响范围。
- 设置：分 Tab（通用 / 人脸 / AI / 关于），减少单页堆砌。

#### 5.2.7 空状态与加载

- 空状态：使用统一 SVG 插画（暗色主题），主文案 18px，副文案 14px `--text-secondary`，并提供行动按钮（如「添加文件夹」）。
- 加载：主区域使用网格 skeleton（4 列 × N 行 shimmer），而非简单文字。

### 5.3 浏览器扩展弹窗

扩展是用户高频入口，虽小但需精致。

#### 5.3.1 整体

- 宽度从 340px 调整为 360px，最大高度 480px。
- 背景 `--bg-surface`，字体使用 `--font-sans`，字号 13px 基准。
- 顶部 header 高度 48px，左侧 Logo 24px + 标题，右侧连接状态 pill。

#### 5.3.2 连接状态

- 已连接：绿色圆点 + 「已连接」文字 pill，背景 `--success-soft`。
- 未连接：红色圆点 + 「未启动」文字 pill，背景 `--danger-soft`，下方提示「启动 PictureButler 后点此重试」。

#### 5.3.3 搜索与列表

- 搜索框高度 34px，内嵌 `search` 图标，placeholder 使用 `--text-tertiary`。
- 刷新按钮改为 32px 图标按钮，与搜索框等高。
- 列表项高度 64px，左侧缩略图 48px 圆角 8px，右侧标题 14px semibold，内容 12px `--text-secondary` 两行截断。
- 列表项悬停背景 `--bg-elevated`，左侧显示 `arrow-right` 图标提示可点击。
- 星标图标使用 `star`（填充黄色）置于标题前，替代字符 `★`。

#### 5.3.4 空状态与底部

- 无星标时显示插画 + 「暂无星标提示词」+ 提示文案。
- 底部 footer 改为「启动 PictureButler」主按钮，置于弹窗底部，减少用户寻找成本。

#### 5.3.5 写入反馈

- 写入成功：顶部绿色 Toast，文案「已写入：提示词标题」。
- 写入失败：顶部红色 Toast，文案明确失败原因。

## 七、交互体验升级

1. **搜索体验**
   - 搜索框 focus 时显示最近搜索/热门标签（可选）。
   - 搜索结果高亮匹配关键词（文件名、描述、标签）。
   - 清空搜索提供一键 `x`。

2. **筛选体验**
   - 已选筛选用 chip 行展示，可逐个移除或一键清除。
   - 标签组合默认 AND，提供 OR 切换，切换时即时反馈结果数。

3. **批量操作**
   - 进入批量模式时顶部出现固定操作栏，左侧显示已选数量，右侧操作按钮按主次排列。
   - 批量操作完成后自动退出批量模式并刷新。

4. **键盘导航**
   - 主网格：方向键移动焦点，Enter 打开，Space 多选，Ctrl+A 全选，Esc 退出批量/清除搜索。
   - 查看器：←/→ 或 A/D 切换，Home/End 首尾，Esc 关闭，Ctrl+滚轮缩放，+/-/0 缩放。
   - 模态框：Tab 在表单内循环，Enter 提交，Esc 关闭。

5. **加载与反馈**
   - 任何耗时操作（搜索、扫描、打标）显示加载态，避免用户重复点击。
   - 进度面板常驻右下角，可随时取消。
   - Toast 不阻塞操作，成功 3s 消失，错误 6s 消失，可手动关闭。

6. **响应式**
   - Web 端支持 1280px / 1024px / 768px / 480px 断点：
     - < 1280px：中间侧栏可收起为抽屉。
     - < 1024px：左侧文件夹栏可收起。
     - < 768px：切换为移动端布局（底部 Tab、单列卡片）。
   - WPF 端最小窗口 900×600，布局自适应缩放。

## 九、验收标准

### 9.1 视觉一致性

- [ ] 三条线（WPF/Web/扩展）使用同一套设计令牌，色值偏差不超过 ±2%。
- [ ] 所有 Emoji 图标被替换为统一图标库。
- [ ] 同一类组件（按钮/输入框/卡片/chip）在不同界面视觉一致。

### 9.2 可用性

- [ ] 主界面信息密度降低，核心操作 3s 内可定位。
- [ ] 图片网格支持至少 3 种比例切换，竖图不再被严重裁剪。
- [ ] 搜索、筛选、批量操作有明确加载反馈。
- [ ] 空状态均有插画/图标 + 文案 + 行动引导。

- [ ] 所有图标按钮有 `aria-label` 或 tooltip。

- [ ] Web 端大型库（>4000 张）加载骨架不阻塞渲染。

## 十、边界与风险

### 10.1 不做的事

- 不替换 WPF 为 WebView2/Tauri（用户已否决）。
- 不引入 Docker、不引入重量级设计框架。
- 不改写后端识别逻辑、不改数据库 schema。
- 不做云同步、移动端、登录体系。

### 10.2 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| WPF 自定义样式破坏虚拟化性能 | 样式只改视觉（Brush/Template），不动 ItemsPanel 与 Virtualizing 逻辑；改完实测滚动 |
| 图标库引入增加体积 | 使用 SVG sprite 或按需子集化 Lucide；扩展只打包必要图标 |
| 色彩变量替换遗漏 | 用脚本扫描所有 `#`/`rgb`/`bg-gray` 硬编码，逐项替换 |
| 用户不习惯新布局 | 保留关键操作位置（左侧文件夹、顶部搜索、右侧详情），只优化视觉 |
| 真机交互需验证 | WPF 交互类改动保留用户真机确认环节 |

## 十一、附录：推荐技术实现

### Web 前端

- 图标：Lucide Vue（`lucide-vue-next`）或内联 SVG sprite。
- 动画：Tailwind CSS 过渡 + 自定义 keyframes。
- 色彩：CSS 变量 + Tailwind `theme.extend.colors` 映射。
- 组件：Vue 3 SFC 或组合式函数封装。

### WPF

- 资源字典：`DesignTokens.xaml`、`Controls.xaml`、`Animations.xaml`。
- 图标：PathIcon / GeometryDrawing，集中 `Icons.xaml`。
- 字体：将 Inter 字体文件放入项目资源或依赖系统已安装字体。
- 动效：使用 `System.Windows.Media.Animation` 的简短动画，列表区域禁用。

### 扩展

- 保持纯 HTML/CSS/JS，不引入框架。
- 图标内联 SVG，颜色继承 CSS 变量。
- 弹窗高度自适应内容，最大高度限制配合内部滚动。

## 十二、一句话结论

**先统一设计系统、再重构核心界面、最后补齐动效与可访问性**，让 PictureButler 在保持原有功能与性能优势的同时，拥有更专业、更一致、更易用的视觉体验。
