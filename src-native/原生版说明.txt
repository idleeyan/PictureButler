PictureButler 原生版（版本 0.62.5）
========================================

架构：原生 Windows 桌面程序（WPF / .NET 10）+ 浏览器扩展拾取器。
识别引擎（原 imgtag）：已**彻底融合**——以 imgtag_native.dll（Rust cdylib）在本程序
进程内运行，无独立 imgtag.exe、无 8520 端口，识别数据仍是同一份 db.sqlite。

【程序本体】
- 文件：PictureButler-绿色版.exe（免安装，双击运行）
- 提示词管理：列表 / 搜索 / 星标 / 详情 / 复制（数据与旧版同库，直接读取）
- 图片库：浏览 / 分页 / 搜索 / 大图查看 / 人物 / 标签（可垂直滚动）
- 人脸识别 / AI 打标 / 人脸缩略图：全部在程序进程内完成
- 本地服务：程序启动后自动监听 127.0.0.1:8189（供扩展连接，并供程序自身读取人脸封面）
- 托盘：点关闭按钮 → 最小化到托盘（程序继续运行，扩展随时可用）
  退出请右键托盘图标 → 退出 PictureButler
- 全局热键：Ctrl + Alt + Space 呼出主窗口
- 界面主题：设置 → 外观 可切换「深色 / 浅色」。主题在启动时装载，切换后会自动重启进程生效
  （重启时若有正在进行的扫描 / 打标任务会被中断，会先弹窗确认）

【浏览器扩展】PictureButler 拾取器
- 目录：extension 文件夹
- 安装：Chrome 打开 chrome://extensions/ → 右上角「开发者模式」→
  「加载已解压的扩展程序」→ 选择 extension 文件夹
- 使用：先运行程序 → 点扩展图标 → 点击星标提示词 → 自动写入当前网页输入框
- 详细说明见 extension\安装说明.txt

【数据】
- 提示词库：%APPDATA%\com.picturebutler.app\prompts.db（与旧版共用，无迁移）
- 图片库：可在设置里配置 imgtag 库路径 + 自建文件夹索引
- imgtag 数据目录（默认 程序目录\imgtag\）：db.sqlite（识别数据）+ models\（ONNX 模型）
  + onnxruntime.dll + imgtag_native.dll

【版本历史】
0.62.5 修复「浏览人物图片或标签相册时，左右快捷键无法翻页」：
  根因与 0.62.4 的证件照/文档同类：打开查看器时只给「全部」和「证件照/文档」附了导航序列，
  人物相册（personPhotos）与标签相册（tagPhotos）没附 → 查看器 _seq 为空，←/→、A/D、
  上一张/下一张全部静默无效。
  修法：补 ImageLibraryService.PersonPhotoRank / TagPhotoRank（名次排序与 PersonPhotos /
  TagPhotos 一致，i.id DESC），并新增 ImgPersonSeq / ImgTagSeq 两条序列，打开人物/标签
  相册图片时异步附上——窗口仍先弹出，序列不阻塞打开。

0.62.4 修复「从证件照/文档页返回图片库后，图片库只剩那十几张」：
  根因两处叠加：① ImgTab_Changed 开头有条拦截（当前是 idPhotos/docPhotos 且分类导航仍选中
     就直接 return），从分类返回图片库时若命中它，_imgMode 会永远卡在分类模式；
  ② 分类模式下 ImgTabAll 往往本来就是选中态，再赋 IsChecked=true 不会触发 Checked 事件，
     于是不重新加载，界面一直停留在分类那十几张上。
  修法：返回图片库时先把 _imgMode 复位为 all，再直接调用页签切换逻辑（而不是改 IsChecked）。
  同时补上功能缺口：证件照 / 文档页里打开图片后，左右键（含 A/D）现在可以在本分类内翻页
  （此前只有「全部」页附加了导航序列；新增 ImageLibraryService.KeywordRank 算名次）。

0.62.3 修复「图片库的图片会整页消失」（数据误清）：
  根因：三处「文件不存在就清索引」的逻辑里，只有设置页的「清理失效图片索引」带了盘符可用性
  判断，另外两处（按页加载时、定时器/窗口激活时的 CleanupGhostCards）直接用 File.Exists ——
  F:（卷标「移动盘」，占 73% 图片）一旦掉线或休眠，整页照片就被当成已删除清掉，索引记录也
  一并删掉，观感就是「图片全消失了」。
  修复：新增唯一判定入口 ImageLibraryService.IsMissing(path) = 文件不存在 **且** 所在盘可访问；
  三处清理与两处页面过滤全部改用它；打开图片时若只是盘不可用，改为提示重连且不动记录。

0.62.2 修复「关闭图片查看器后主窗口被压到底层」：
  查看器是 Show() 出来的**非模态**窗口，关闭时 Windows 只会激活 z-order 里的「下一个」窗口，
  那个窗口往往是别的程序；设有 Owner 也不够。现在在 OnClosed 里显式 Activate + Focus 主窗口
  （若主窗口被最小化则先还原）。删除后自动关闭、手动关闭两条路径都会走到这里。
  其余子窗口都是 ShowDialog() 模态，WPF 会自动恢复 owner 激活，无需处理。

0.62.1 修复「删除图片后程序界面被压到其他窗口后面」：
  根因是 SHFileOperation（回收站删除）的 hwnd 一直传空句柄 —— Shell 没有所有者窗口时
  会去激活 Explorer / 桌面，本程序窗口因此掉到底层。现在传入调用方窗口句柄（主窗口与
  查看器窗口均已传），并在删除完成后、若窗口原本处于激活态则 Activate() 兜底。

0.62.0 光标改为**只用一种**：
